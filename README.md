# LeoMox Feedback Call Agent

Structured outbound feedback-survey module (Telugu / English / Hindi) with secure session auth and LeoMox branding.
Node 20+/Express, PostgreSQL (Neon), plain-JS frontend served by the same server (no build step).

**Status: mock mode only.** Telephony, STT, TTS and the AI classifier are mock adapters; no real calls are placed and every
call record is flagged `is_mock`. Not implemented: real provider adapters, Cloudflare R2 recording storage, recording retention/deletion.

## Run locally
    npm ci
    cp .env.example .env     # set DATABASE_URL (a local or Neon database) and SUPERADMIN_*
    set -a; . ./.env; set +a; npm start      # migrates, seeds the SuperAdmin, listens on :3000

## Tests
    npm test                                  # in-memory Postgres (pg-mem)
    TEST_DATABASE_URL=postgres://user@host/db npm test    # real Postgres (isolated schema per test)

## Deploy: Git -> Render -> Neon
1. Neon: create a project/database and copy the connection string (keep `sslmode=require`).
2. Push this folder to a Git repo (GitHub/GitLab).
3. Render: New > Blueprint > pick the repo (uses `render.yaml`), or New > Web Service with build `npm ci`, start `npm start`.
4. Set the secret env vars when prompted: `DATABASE_URL`, `SUPERADMIN_EMAIL`, `SUPERADMIN_PASSWORD` (10+ chars).
   `WEBHOOK_SIGNING_SECRET` is generated by the blueprint.
5. Deploy. On first start the app applies `migrations/*.sql` and creates the SuperAdmin. Health: `/healthz`, `/readyz`.
6. Log in at your Render URL with the SuperAdmin, create users (System tab), then create a campaign and import contacts.
Migrations run at startup in a transaction and tolerate several instances starting together. Set `AUTO_MIGRATE=false` and run
`npm run migrate` as a deploy step if you prefer.

## Sessions and security
- Server-side sessions (table `sessions`, only a SHA-256 of the cookie value is stored). Session cookie: HttpOnly, SameSite=Lax,
  Secure in production, no expiry (dropped when the browser closes).
- Cookie name includes a per-tab id (kept in `sessionStorage`), so a new tab must log in and tabs never log each other out.
  A tab restored with Ctrl+Shift+T keeps its id and may stay signed in until the idle timeout.
- Idle timeout (`SESSION_IDLE_MINUTES`, default 15) and absolute lifetime (`SESSION_MAX_HOURS`, default 12) enforced on every request;
  expired sessions are revoked in the database. The client shows "Your session has expired. Please log in again."
- CSRF: `X-CSRF-Token` on all state-changing requests plus same-origin check. Login lockout after 5 failures (15 min), rate limit on login.
- Roles: VIEWER < MANAGER < ADMIN < SUPER_ADMIN. Viewers see aggregates and masked call lists; transcripts, contacts, imports,
  runs and exports need MANAGER; audit log and user creation need ADMIN.
- No passwords or tokens in localStorage. Numbers are masked in every API response and export. Strict CSP (scripts from self only).

## Webhook
`POST /api/webhooks/telephony` with JSON `{event_id, provider_call_id, type}` and header `X-LeoMox-Signature: <hex HMAC-SHA256 of raw body>`.
Duplicate `event_id`s are ignored; stale or out-of-order events don't overwrite a later state; `opted_out` adds the number to suppression.
